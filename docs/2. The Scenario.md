# The Scenario

## Movie Picture Pipeline

You are the DevOps engineer for a development team that manages a web application that is a catalog of Movie Picture movies. The team needs to automate its development workflows to accelerate its release cycle. You will use GitHub Actions to automate testing, building, and deploying applications to an existing Kubernetes cluster.

The team's project is comprised of 2 applications.

1. A frontend UI built written in Typescript, using the React framework
2. A backend API written in Python using the Flask framework.

Within the `starter` directory in the **Project Workspace** page, you'll find two folders, one named `frontend` and one named `backend`, where each application's source code is maintained.

Use the team's Deliverable Notes (Steps 1 & 2) and the information contained on the following pages to create CI/CD pipelines to meet the teams' needs.

Instructions are also contained in the README found in **Project Workspace**.

The starter code for this project is contained in the **Project Workspace**.

To work on the project, you will need to:

1. Create a new GitHub repository.
2. Initialize a Git repository in the Project Workspace using `workspace` as the root directory.
3. Add the workspace files to the new GitHub repository. Use the previous lessons as a guide, or follow [these GitHub directions](https://docs.github.com/en/migrations/importing-source-code/using-the-command-line-to-import-source-code/adding-locally-hosted-code-to-github).
4. Create a CloudFormation template to create the necessary resources, or use a provided Terraform manifest to create the resources. The Terraform files have been provided in the Project Workspace `setup` directory.

## After implementing your project, tear down your AWS resources

This can be done in several ways, including:

- From the AWS console, if using CloudFormation.
- From the `setup/terraform` directory - run the following code: `terraform destroy`, if using Terraform.
